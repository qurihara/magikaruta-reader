# まじかるた 読み上げ（majikaruta-reader）

カードゲーム「まじかるた」で、読み手の代わりに電子音を鳴らすウェブアプリです。
「読む」を押すと準備音が鳴り、そのあと「ピン」という電子音が札の値の回数だけ鳴ります。最後の1回だけ高い音になるので、遊ぶ人はそこで読みの終わりを知ります。
まじかるたは栗原一貴さんと丸山礼華さんの作品で（ProtoPedia 7523、Creative Hack Award 2025 特別賞）、
このアプリは Yohei Yanase さんの Unity 版（https://unityroom.com/games/magikaruta ）を、スマートフォンでも使えるウェブアプリとして作り直したものです。

素の HTML、CSS、JavaScript だけで書いてあり、ビルドの工程も外部のパッケージもありません（Google Fonts の書体だけを読み込みます）。
版の数字は `js/config.js` の `APP_VERSION` の1か所で管理し、画面の右下に出します。直したら必ず上げ、末尾の「変更履歴」に1行書いてください。

## 遊び方

### 現行ルール（1〜12、空札なし）

1. 1から12の数字が書かれた札を12枚用意します（トランプの A〜Q でも遊べます）。
2. よく混ぜて配ります。2人なら6枚ずつです。数字を表にして自分の前に並べます（自陣）。
3. 最初の音が鳴るまでは、手を札に乗せずに待ちます。
4. 「読む」を押すと、準備音のあとに電子音が1〜12回鳴ります。最後の1回だけ高い音です。鳴った回数と同じ数字の札を取ります。
5. 相手の陣の札を取った人は、自分の陣の札を1枚相手に送ります。
6. 自分の陣の札が先に無くなった人の勝ちです。

アプリは、まだ読んでいない値から一様に無作為に1つを選んで読みます。同じ値は1つのゲームの中で2回読みません。
全部を読み終えると「読む」のボタンが「新しいゲーム」に変わり、押すと次のゲームを始めます。
途中で打ち切るときは「新しいゲーム」のボタンを押します（確認のあと、いまのゲームは途中までの記録として残ります）。

### 空札のルール

設定で値の範囲を 1〜13 にし、「空札のルールで遊ぶ」を入れます。13枚を混ぜて2人に6枚ずつ配り、残りの1枚を伏せたまま脇へ置きます。
アプリはどの値が空札かを知らず、13の値をすべて無作為の順に読みます。空札の値が読まれたら誰も札に触れてはいけません。触れたらお手つきです。
「空札のルールで遊ぶ」の印は読み方を変えず、画面の表示と記録にだけ残ります。

### 種類のあるルール（赤と黒など）

設定で札の種類を2〜4にすると、同じ値の札が種類の数だけ読まれます（たとえば2種類なら、赤の1〜12と黒の1〜12の24枚）。
アプリは、最後の音の高さと音色で種類を伝えます。

| 種類 | 2種類のときの呼び名 | 最後の音 | 点滅の色 |
|---|---|---|---|
| 1 | 赤（♥ハート） | 1760 Hz、澄んだ音（正弦波） | 朱 #ff2a12 |
| 2 | 黒（♠スペード） | 440 Hz、澄んだ音（正弦波） | 藍 #1e50ff |
| 3 | ♦ダイヤ | 1760 Hz、ざらついた音（矩形波） | 山吹 #ffc400 |
| 4 | ♣クラブ | 440 Hz、ざらついた音（矩形波） | 緑 #12b04a |

通常の電子音（880 Hz）に対して、赤の札は1オクターブ上、黒の札は1オクターブ下で終わります。
2種類なら高さだけで聞き分けられ、3種類と4種類では音色（澄んだ音とざらついた音）も加わります。
赤の札（♥と♦）を高い音、黒の札（♠と♣）を低い音にそろえたので、トランプの赤と黒の区別と一致します。
設定の「音の確認」で、種類ごとの最後の音を聞き比べられます。

## 設定の意味

| 項目 | 意味 | 既定 |
|---|---|---|
| 値の範囲 | 読む値を 1〜N にします。N は 2〜13（13 はトランプの K）。 | 12 |
| 札の種類 | 同じ値の札の種類の数（1〜4）。 | 1 |
| 空札のルールで遊ぶ | 記録と表示のための印。読み方は変わりません。 | 切 |
| 電子音の間隔 t | 電子音の鳴り始めから次の鳴り始めまでの秒数。0.1、0.2、0.4、0.8、1.6 秒の5水準、自由な値（0.05〜3 秒）、「ゲームごとに無作為」から選びます。 | 0.4 秒 |
| 準備音から最初の音まで | 準備音の鳴り始めから最初の電子音の鳴り始めまでの秒数（0.3〜3 秒）。 | 1.0 秒 |
| 音量 | 0〜1。 | 0.7 |
| 音に合わせて画面全体を点滅させる | 下の「点滅」を参照。 | 切 |
| 最後の点滅を種類の色にする | 種類が2つ以上のとき、最後の点滅を種類の色にします。切ると朱になります。 | 入 |
| 点滅の遅れの補正 | 点滅を音より遅らせる量（ミリ秒、−300〜500）。外付けのスピーカで音が遅れるときに正の値にします。 | 0 |
| ゲームの番号と t を大きく表示する | 天井カメラの画角で読めるように、番号と t を大きく出します。 | 切 |
| 記録の見出し | 記録の各行に付ける名前（会場や端末の名前）。 | 空 |
| 次のゲームの番号 | 次に始めるゲームの番号。 | 続き番号 |

ルールと t の変更は、読んでいる途中のゲームには反映せず、次のゲームから使います。まだ1枚も読んでいないゲームなら、すぐに作り直します。

「ゲームごとに無作為」を選ぶと、アプリは5水準を袋に入れてかき混ぜ、ゲームのたびに1つずつ取り出します。
5ゲームごとに5水準が1回ずつ出るので、ワークショップの途中で終えても水準の回数が大きく偏りません。袋の中身は端末に保存され、アプリを開き直しても続きから取り出します。

現行の公式アプリの電子音の間隔は、公開されている資料（unityroom の説明、cosense の記録）からは分かりませんでした。そのため既定の t を 0.4 秒にしてあります。
参考までに、丸山さんが2025年12月に p5.js で作った「EzKaruta-like Reader」は、間隔を 0.26 秒、準備音から最初の音までを 0.61 秒にしていました。

## 音

アプリはすべての音を Web Audio の発振器で作り、「読む」を押した時点で、1回の読みの全部の音を AudioContext の時刻で予約します。setTimeout では鳴らさないので、端末が忙しくても電子音の間隔はずれません。

- 準備音：523 Hz（ド）の三角波を 0.22 秒鳴らし、鐘のように減衰させます。
- 通常の音：880 Hz の正弦波を、t の半分か 0.08 秒の短いほうの長さで鳴らします。
- 最後の音：種類が1つなら 1760 Hz の正弦波を、0.22 秒鳴らします。

通常の音と最後の音の高さは、同じ案件の収集Bのアプリ（`../collection-b-app`）と同じにしてあります。紙のフリープレイ（収集A）とPCの実験（収集B）で、参加者が聞く音をそろえるためです。

iPhone の Safari では、最初の画面の「音を出してはじめる」のタップで AudioContext を起こします。Safari 16.4 以降では `navigator.audioSession.type = "playback"` も設定します。
それでも本体の消音スイッチが入っていると鳴らない場合があるので、最初の画面と本体の画面に注意を出しています。
画面が消えないように Wake Lock を使います（使えない端末では何もしません）。

## 点滅（天井カメラとの同期）

「音に合わせて画面全体を点滅させる」を入れると、読んでいる間は画面全体が黒くなり、音の時刻にだけ色が出ます。

- 準備音：灰 #8c8c8c、0.15 秒
- 通常の音：白、t の半分か 0.1 秒の短いほう
- 最後の音：朱 #ff2a12（種類があるときは上の表の色）、0.35 秒

黒い地の上で光らせるので、明るい画面の設定でも暗い画面の設定でも、カメラの映像で点滅を見分けられます。
点滅の間も、ゲームの番号と t の札だけは前に出したままにします（生成りの札の上に墨の文字）。

アプリは点滅の時刻を、音の予約時刻を performance.now の時間軸に換算し、AudioContext が報告する出力の遅れ（`baseLatency + outputLatency`）と設定の補正を足して決めます。
描画は requestAnimationFrame の各コマで行い、画面が実際に光ったコマの時刻を記録に残します。コマが落ちて点滅の時間を丸ごと飛ばしたときは、次の点滅が始まる前なら1コマだけ遅れて光らせます（点滅の数を音の数と照合できるように）。

## 記録

アプリはゲームごとに、開始の時刻、設定（N、種類の数、空札の印、t の決め方と値、準備音の間）、読む順、読みごとの値と種類、各音の予約時刻を、ブラウザの localStorage に保存します。
各音の時刻は AudioContext の時刻、performance.now、Date.now の3つの時間軸で残します。3つの時計を同じ瞬間に読んだ値を基準にして換算します（Kikiwake と収集Bのアプリと同じ換算）。

アプリは、記録をその端末のそのブラウザにだけ残します。プライベートブラウズでは残らないことがあります。

### 書き出し

設定の「運営者」の欄から書き出します。

- **JSON**：`majikaruta-log-YYYYMMDD-HHMM.json`。全部の項目をそのまま含みます（読む順 `order`、読み `reads`、各音 `events`、点滅の予定と実際の時刻、端末の画面の大きさとユーザエージェント）。
- **CSV**：`majikaruta-log-YYYYMMDD-HHMM.csv`。1行が1つの音（準備音を含む）です。Excel で文字化けしないように先頭に BOM を付けています。

CSV の列は次のとおりです。

`label, app_version, game_no, game_id, game_started_iso, max_value, kinds, blank_rule, t_mode, t_sec, prep_gap_sec, read_index, value, kind_index, kind_label, pressed_perf_ms, pressed_epoch_ms, event_index, event_role, ctx_time_s, perf_ms, epoch_ms, epoch_iso, flash_scheduled_perf_ms, flash_shown_perf_ms, output_latency_s, base_latency_s`

`event_role` は `prep`（準備音）、`tone`（通常の音）、`last`（最後の音）のどれかで、`event_index` は準備音が 0、電子音が 1 から値までです。
`epoch_ms` は Date.now の時間軸（1970年からのミリ秒）なので、カメラの映像の時刻と突き合わせるときに使います。

「記録を消す」を2回押すと、全部の記録が消えます。消す前に書き出してください。

### 答えの確かめ方（運営者用）

読み終えたあと、「答えを確かめる」を長押し（約0.9秒）すると、直前の読みの値と種類、このゲームで読んだ順が表示されます。画面を触るか8秒たつと消えます。
読んでいる最中と、まだ1枚も読んでいないときは押せません。短く押しただけでは表示しません。

## 配信の仕方

このアプリは GitHub Pages から配信している。スマートフォンでもパソコンでも、次の URL を開けば使える。

https://unryu.org/majikaruta-reader/

ES モジュール（`<script type="module">`）を使うので、`file://` では動かない。手元で動かすときは、このフォルダでローカルのサーバを起こす。

```
python3 -m http.server 8797
```

そのうえで http://localhost:8797/ を開く。Wake Lock（画面を消さない機能）は HTTPS でしか働かないので、スマートフォンでは GitHub Pages の URL を使う。

## 検査

純粋な関数（読む順の生成、設定の正規化、電子音の時刻表、t の袋、記録の CSV）を `js/core.js` にまとめ、`test/core.test.js` で検査します。

```
/opt/homebrew/bin/node --test test/*.test.js
```

## ファイル

- `index.html`：画面の骨組み（最初の画面、本体、点滅の幕、答えの表示、遊び方、設定、確認）
- `css/style.css`：見た目（和紙の地、墨の文字、取り札の形の「読む」、明るい画面と暗い画面）
- `js/config.js`：版の数字と定数（音の高さ、点滅の色、種類、t の5水準、既定の設定）
- `js/core.js`：純粋な関数
- `js/audio.js`：Web Audio の予約
- `js/flash.js`：点滅
- `js/storage.js`：localStorage への保存
- `js/app.js`：画面の操作とゲームの進行
- `test/core.test.js`：検査
