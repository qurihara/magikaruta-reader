# まじかるた 読み上げ（magikaruta-reader） / MagiKaruta Reader

カードゲーム「まじかるた」で、読み手の代わりに電子音を鳴らすウェブアプリです。
「読む」を押すと準備音が鳴り、そのあと「ピン」という電子音が札の値の回数だけ鳴ります。最後の1回だけ高い音になるので、遊ぶ人はそこで読みの終わりを知ります。
まじかるたは栗原一貴さんと丸山礼華さんの作品で（ProtoPedia 7523、Creative Hack Award 2025 特別賞）、
このアプリは Yohei Yanase さんの Unity 版（https://unityroom.com/games/magikaruta ）を、スマートフォンでも使えるウェブアプリとして作り直したものです。

素の HTML、CSS、JavaScript だけで書いてあり、ビルドの工程も外部のパッケージもありません（Google Fonts の書体だけを読み込みます）。
公開版には英語版があります（v0.4.0、英語の題名は MagiKaruta）。下の「英語版」の節を見てください。

版の数字は `js/config.js` の `APP_VERSION` の1か所で管理し、最初の画面と本体の画面の下に出します。v0.3.0 からは、変更のたびに2つ目の数字（マイナーの版）を1つ上げ（v0.3.0 の次は v0.4.0）、末尾の「変更履歴」に1行書いてください。sw.js の `CACHE` の名前も同じ版に合わせます。

## 2つのページ

このリポジトリには、目的の違う2つのページがあります。音と点滅の部品と純粋な関数は2つのページで共有し、画面の処理と保存の仕方は分けてあります。

- **公開版**（`index.html`）：https://unryu.org/magikaruta-reader/
  遊ぶ人のためのページです。使う人の体験を重視して簡素にしてあり、研究用の機能は出しません。
  端末に保存するものは、選んだルールと電子音の間隔だけです。ゲームの記録は残しません。
- **実験用のページ**（`lab.html`）：https://unryu.org/magikaruta-reader/lab.html
  実験の当日に、監督者が1台の端末（ノートPCかタブレット）で、読み上げと進行管理をまとめて行うページです。
  条件（電子音の間隔 t と空札の有無）を無作為の順に回し、ゲームと読みと音の時刻を記録し、天井のカメラとの同期のために画面を点滅させます。
  公開版からは辿れないようにしてあります（実験用のページの下にだけ、公開版への案内があります）。

公開版から外したもの：4種類のルール、値の範囲の自由な指定、t の自由な値と「ゲームごとに無作為」、カメラ用の全画面の点滅、点滅の遅れの補正、ゲームの番号と t の大きな表示、記録の保存と書き出し、記録の見出し、音量の設定。
このうち研究に要るもの（点滅、遅れの補正、番号と t の大きな表示、記録、音量）は、実験用のページに移しました。

## 英語版（English）

公開版の画面は、日本語と英語の2つの言語で表示できます（v0.4.0）。英語の題名は「MagiKaruta」、副題は「Reader」です。
English speakers can open the English version directly: https://unryu.org/magikaruta-reader/?lang=en

- **切り替え方**：最初の画面の右上と、本体の画面の下の欄に、「日本語」と「English」の小さな2つのボタンがあります。押すとその場で全部の文言が切り替わります。
- **言語の決め方**：アプリは、次の順に言語を決めます。
  1. URL の `?lang=en` か `?lang=ja`（配る相手に英語版の URL を渡せるように、最優先にしてあります）
  2. 前に選んだ言語（端末の localStorage に保存します。読めないときは黙って次に進みます）
  3. 端末の言語（`navigator.language` が ja で始まれば日本語、それ以外は英語）
- `?lang=` の付いた URL で開いたあとにボタンで言語を切り替えると、アプリは URL の `?lang=` も選んだ言語に書き換えます。再読み込みしても、選んだ言語のままです。
- 英語版の遊び方の画面からも、ルール紹介の映像へのリンクを張っています。映像のナレーションは日本語なので、リンクには「Rules video (in Japanese)」と添えてあります。電子音は日本語版と同じです。
- 実験用のページ（`lab.html`）は日本語だけです。

画面の文言は、日本語と英語の両方を `js/i18n.js` の辞書の1か所にまとめてあります。`index.html` には文言を書かず、`data-i18n`（文字）、`data-i18n-html`（HTML）、`data-i18n-attr`（`aria-label` などの属性）の印で辞書の鍵を指し、`app.js` が差し替えます。ルールの名前と要約、電子音の間隔の5段階の言葉、札の色の呼び名も、この辞書にあります。
文言を足したり直したりするときは、日本語と英語の両方の鍵を書きます。`test/i18n.test.js` が、2つの辞書の鍵の集合が一致すること（訳し漏れが無いこと）と、`index.html` の印が指す鍵がすべて辞書にあることを検査します。

英語の用語は、次のように対応させています。

- 札：card、自陣：your side、敵陣：your opponent's side
- 空札：dead card（初出で「a number not on the table」と説明）、お手つき：fault（初出で説明を添える）
- 送り札：send one of your cards to the opponent
- 電子音：beep、準備音：cue tone、電子音の間隔：Beep interval
- いつものルール：Standard、空札あり：Dead card、赤と黒：Red & Black、ほかの遊び方：Other ways to play
- 電子音の間隔の5段階：Very fast、Fast、Normal、Slow、Very slow
- 読む：Read、答えを確かめる（長押し）：Check answer（hold）、新しいゲーム：New game、遊び方：How to play、ルールと速さ：Rules & speed

## 公開版の遊び方

### ルール

「ルールと速さ」で3つから選びます。

- **いつものルール**：1〜12 の12枚で、空札はありません。2人なら6枚ずつ配り、数字を表にして自分の前に並べます（自陣）。鳴った回数と同じ数字の札を取り、相手の陣の札を取ったら自分の陣の札を1枚相手に送ります。自分の陣の札が先に無くなった人の勝ちです。
- **空札あり**：1〜13 の13枚を混ぜて2人に6枚ずつ配り、残った1枚を伏せたまま脇へ置きます（空札）。アプリはどの値が空札かを知らず、13の値をすべて無作為の順に読みます。空札の値が読まれたら誰も札に触れてはいけません。触れたらお手つきで、相手から札を1枚送られます。
- **赤と黒**（「ほかの遊び方」の中）：赤の1〜6と黒の1〜6の12枚で遊びます。鳴った回数で数字を、最後の音の高さで色を伝えます。赤の札は通常の音の1オクターブ上（1760 Hz）、黒の札は1オクターブ下（440 Hz）で終わります。

アプリは、まだ読んでいない札から一様に無作為に1枚を選んで読み、同じ札を1つのゲームの中で2回読みません。
全部を読み終えると「読む」のボタンが「新しいゲーム」に変わります。途中で打ち切るときは「新しいゲーム」を押します（確認が出ます）。

### 電子音の間隔

「ルールと速さ」で、電子音の鳴り始めから次の鳴り始めまでの秒数を5つから選びます。

- とても速い：0.1 秒
- 速い：0.2 秒
- ふつう：0.4 秒（はじめの設定）
- ゆっくり：0.8 秒
- とてもゆっくり：1.6 秒

間隔を変えると、次に読む札から変わります。ルールを変えると、新しいゲームを始めます。

### 音に合わせた控えめな点滅と、答えの確認

公開版では、電子音に合わせて「読む」の札をほのかに光らせます（準備音は淡い灰、通常の音は金、最後の音は朱、赤と黒では最後の音を色ごとに）。耳が聞こえにくい人の助けにもなるように、常に光らせます。
「答えを確かめる」を長押し（約0.45秒）すると、直前に読んだ値と、このゲームで読んだ順が出ます。画面を触るか8秒たつと消えます。

### 読まれた札の履歴

本体の画面の「読んだ札」の下に、そのゲームの全部の値を小さな札で並べます（いつものルールは 1〜12、空札ありは 1〜13、赤と黒は赤の段と黒の段）。読まれた札は薄くなり、右上に読まれた順の番号が付きます。その下の「読んだ順」の行に、読まれた値を順に並べます（例：7 → 3 → 11）。
答えが画面に出ると遊びにならないので、直前の読みは、次の「読む」を押した時点か、「答えを確かめる」を長押しして答えを見た時点で、はじめて履歴に加わります。それまでは「読んだ順」の行の末尾に「？」を出します。新しいゲームを始めると、アプリは読まれた札の履歴を空にします。

## 実験用のページ

### 画面の構成

PC の幅では左右の2列に分かれます（スマートフォンの幅では縦に並びます）。押し間違えを防ぐために、「読む」と「次のゲームへ」と重い操作を、画面の離れた場所に置いてあります。

- 左の列（読み上げ）
  - 条件の札：ゲームの番号、間隔 t、配り方（「6枚ずつ・空札1枚」など）を大きく出します。空札ありのゲームでは、札の下の縁が朱になります。
  - 読んだ札の数と、読んだ札の並び（値は出しません）。
  - 「読む」の大きな取り札。
  - 「読み直す」（直前の札をもう一度）、「止める」（読んでいる最中だけ）、「答えを確かめる」（長押し）。
- 右の列（進行）
  - 進行の板：いまの段階に応じて、「次のゲームへ」（常磐色の大きなボタン）、「後回し」、「条件を手で指定する」、「ルールを参加者に見せる」、「ゲームを終える」が出ます。
  - やり直しと取り消し：朱の破線で囲んだ欄です。どちらも2回続けて押すと実行します。
  - 卓と名札：いまのゲームに参加した卓と、各卓の2人の名札の番号、メモを書きます。空のままでもかまいません。次のゲームには、このゲームの卓と名札を写します。
  - 条件の袋：条件ごとの有効なゲーム（完了か途中終了）の数と、この巡でまだ行っていない条件（●）を表で示します。
- 下：ゲームの記録の一覧。項目を開くと、読んだ値（読み直しと中断の印つき）、卓と名札とメモの書き換え、そのゲームの取り消しができます。
- 上の右：「保存済み」の時刻、「書き出し・読み込み」、「設定」。

### 条件の回し方

既定の条件は、電子音の間隔 t（0.1、0.2、0.4、0.8、1.6 秒）× 空札の有無の10通りです。

- 空札なし：1〜12 の12枚から、2人に6枚ずつ配ります。
- 空札あり：1〜13 の13枚から、2人に6枚ずつ配ります。残った1枚が空札です。

アプリは条件を固定の順に並べず、「まだ行っていない条件の袋」から無作為に1つを引きます。袋が空になったら、10条件を詰め直して次の巡に進みます（ゲームの記録に何巡目かを残します）。
後回しや取り消しで条件を袋に戻すので、途中で中断したり順番を入れ替えたりしても、条件ごとの回数の偏りが小さく保たれます。
同時に遊ぶ組（1〜4組）は同じ電子音を聞くので、1ゲームの条件は全部の組で同じです。

監督者は、「設定」の「条件の水準」で条件の水準を変えられます（t の水準を「,」で区切って書き、空札なしと空札ありの一方だけにもできます）。水準を変えて保存すると、アプリは袋を空にし、次に引くときに新しい水準で次の巡を始めます。

### 当日の監督者の手順

- 手順A1：会場で `lab.html` を開き、「音を出してはじめる」を押します。ノートPCは電源につなぎ、スリープしない設定にします。外付けのスピーカを使うときは、「設定」の「音を確かめる」で音量を合わせます。
- 手順A2：「設定」で、同時に遊ぶ卓の数と記録の見出し（会場や日付）を入れます。空札のルールの説明の文も確かめます。
- 手順A3：「最初のゲームを用意する」（2回目からは「次のゲームへ」）を押します。条件の札に、ゲームの番号、t、配り方が大きく出ます。
- 手順A4：参加者に配り方（「6枚ずつ・空札1枚」など）を伝えて配ってもらいます。空札ありのゲームでは、必要に応じて「空札のルールを参加者に見せる」を押し、画面いっぱいの説明を見せます（直前の有効なゲームが空札なしだったときは、このボタンが朱の枠で目立ちます）。
- 手順A5：卓と名札の欄に、参加した卓と名札の番号を入れます（空でもかまいません）。
- 手順A6：準備ができたら「読む」（またはスペースキー）を押します。読んでいる間は画面全体が黒くなり、上にゲームの番号と t と配り方が大きく出たまま、音の時刻に画面が光ります。
- 手順A7：札を取り終えたら、次の「読む」を押します。これを繰り返します。
- 手順A8：札が無くなったら「ゲームを終える」を押し、終え方を選びます（完了、途中終了、無効）。
- 手順A9：アプリは自動では次へ進みません。休憩や説明をはさみ、準備ができたら「次のゲームへ」を押して手順A3に戻ります。
- 手順A10：終わったら「書き出し・読み込み」から、JSON と CSV（音ごと、ゲームごと）を書き出します。途中でも、休憩のたびに JSON を書き出しておくと安全です。

### トラブルのときの操作

- 操作T1（聞き逃し、物音）：「読み直す」を押すと、直前の札と同じ値をもう一度読みます。記録には「読み直し」として残り、読む順は進みません。
- 操作T2（読んでいる最中に止めたい）：「止める」（点滅の画面では右下のボタン、または Esc キー）を押します。その読みは「中断」として残り、どの音まで鳴ったかも記録します。そのあとの「読む」は、中断した札と同じ値を読み直します。
- 操作T3（同じ条件でもう一度やりたい）：「やり直す」を2回押します。いまの回に「やり直し」の印を付けて残し、同じ条件の新しいゲーム（新しい番号）を用意します。条件の袋は変わりません。
- 操作T4（そのゲームを記録に使わない）：「取り消す」を2回押すか、「ゲームを終える」で「無効」を選んで2回押します。そのゲームに「無効」の印を付け、条件を袋に戻すので、同じ条件をあとでもう一度行えます。終えた前のゲームも、記録の一覧から取り消せます。
- 操作T5（まだ始めていない条件を後にしたい）：「後回し」を押すと、その条件を袋に戻し、別の条件を引きます。ゲームの番号は変わりません。
- 操作T6（条件を自分で決めたい）：「条件を手で指定する」で t と空札の有無を選び、1ゲームを行います。記録に「手動」の印が付き、条件の袋は使いません（用意してあったゲームの条件は袋に戻します）。
- 操作T7（終え方を押し間違えた）：完了か途中終了で終えた直後なら、「終えたのを取り消して、このゲームを続ける」で進行中に戻せます。
- 操作T8（ページを閉じた、再読み込みした、電池が切れた）：同じ端末の同じブラウザで `lab.html` を開き直すと、続きから戻ります。読んでいる最中に落ちた読みは「中断」として記録され、「読む」で同じ値を読み直せます。
- 操作T9（端末を替えたい）：元の端末で JSON を書き出し、別の端末の「書き出し・読み込み」で読み込み、ボタンを2回押します。いまの記録を自動で書き出してから置き換えるので、元の記録は失われません。
- 操作T10（袋を初めからにしたい）：「設定」の「袋を作り直す」を2回押すと、袋に残った条件を捨て、次に引くときに全部の条件で次の巡を始めます。

重い操作（やり直し、取り消し、無効、読み込み、全部消す、袋を作り直す）は、どれも2回続けて押したときだけ実行します。1回目でボタンの文字が「もう一度押すと…」に変わり、4秒のうちに2回目を押さなければ元に戻ります。ブラウザの確認の小窓は使いません。

### 空札のルールの説明

「空札のルールを参加者に見せる」で出す説明の文は、「設定」で書き換えられます。お手つきの罰がまだ決まっていないためです。
既定の文は「空札が読まれたら、どの札にも触れません。触れたらお手つきで、相手から 1 枚送られます」です。

### 記録

アプリは、操作のたびに状態の全部を端末の IndexedDB に保存します（使えないブラウザでは localStorage に保存し、画面にその旨を出します）。
ゲームごとに、ゲームの番号、巡目、条件、手動かどうか、やり直しの元のゲーム、開始と終了の時刻、終え方、参加した卓と名札の番号、メモを残します。
読みごとに、値、読み直しかどうか（その理由）、中断かどうか（その理由）、各音の時刻を、AudioContext、performance.now、Date.now の3つの時間軸で残します。点滅の予定の時刻と、画面が実際に光ったコマの時刻も残します。
performance.now の原点はページを開き直すたびに変わるので、読みごとに原点（`performance.timeOrigin`）も残します。監督者の操作（後回し、手動の指定、やり直し、取り消しなど）の履歴も残します。

「書き出し・読み込み」から、次の3つを書き出します。

- **JSON**（`majikaruta-lab-YYYYMMDD-HHMM.json`）：状態の全部です。別の端末で読み込めば、そのまま続きから進められます。
- **音の CSV**（`majikaruta-lab-tones-YYYYMMDD-HHMM.csv`）：1行が1つの音（準備音を含む）です。Excel で文字化けしないように、先頭に BOM を付けています。
- **ゲームの CSV**（`majikaruta-lab-games-YYYYMMDD-HHMM.csv`）：1行が1つのゲームです。映像と照らし合わせて卓や名札を補うときに使います。

音の CSV の列は、v0.1.0 の列を土台に、ゲームの印と読みの印の列を足したものです。

`label, app_version, game_no, game_id, game_started_iso, round, condition_key, manual, retry_of, outcome, game_ended_iso, tables, max_value, kinds, blank_rule, deal_per_player, blank_cards, t_mode, t_sec, prep_gap_sec, read_index, read_pos, value, kind_index, kind_label, reread, reread_reason, read_status, interrupt_reason, pressed_perf_ms, pressed_epoch_ms, perf_time_origin_ms, event_index, event_role, event_played, ctx_time_s, perf_ms, epoch_ms, epoch_iso, flash_scheduled_perf_ms, flash_shown_perf_ms, output_latency_s, base_latency_s`

- `outcome`：`completed`（完了）、`stopped`（途中終了）、`void`（無効）、`redo`（やり直し）。進行中なら空です。
- `t_mode`：袋から引いた条件は `bag`、手で指定した条件は `manual`。
- `read_index` は読みの通し番号、`read_pos` は読む順の何番目の札か（0 から）です。読み直しでは `read_pos` が前の読みと同じになります。
- `reread_reason`：`manual`（「読み直す」を押した）、`after-interrupt`（中断のあとの読み直し）。
- `read_status`：`done`（最後まで鳴った）、`interrupted`（中断）。`interrupt_reason` は `stop`（止める操作）、`reload`（再読み込みや閉じ直し）、`pagehide`（ページを離れた）、`import`（別の端末から読み込んだ）のどれかです。
- `event_played`：中断した読みで、その音が止める前に鳴ったかどうか（1 か 0）。再読み込みで中断した読みでは分からないので空です。
- `tables`：参加した卓と名札の番号。例「1[12/15] 2[3/4]」。
- `epoch_ms` は Date.now の時間軸（1970年からのミリ秒）なので、カメラの映像の時刻と突き合わせるときに使います。

ゲームの CSV の列は `label, app_version, game_no, game_id, round, condition_key, t_sec, blank_rule, max_value, deal_per_player, blank_cards, manual, retry_of, status, outcome, previous_outcome, created_iso, game_started_iso, game_ended_iso, cards_read, cards_total, reads, rereads, interrupted, tables, memo` です。

### カメラとの同期（点滅）

「設定」の「カメラ用の点滅」を入れておくと（既定で入っています）、読んでいる間は画面全体が黒くなり、音の時刻にだけ色が出ます。

- 準備音：灰 #8c8c8c、0.15 秒
- 通常の音：白、t の半分か 0.1 秒の短いほう
- 最後の音：朱 #ff2a12、0.35 秒

点滅の上には、ゲームの番号、t、配り方を、生成りの帯に墨の文字で大きく出し続けます。
アプリは点滅の時刻を、音の予約時刻を performance.now の時間軸に換算し、AudioContext が報告する出力の遅れ（`baseLatency + outputLatency`）と設定の補正（点滅の遅れの補正、ミリ秒）を足して決めます。外付けのスピーカで音が遅れて聞こえるときは、補正を正の値にします。
描画は requestAnimationFrame の各コマで行い、画面が実際に光ったコマの時刻を記録に残します。コマが落ちて点滅の時間を丸ごと飛ばしたときは、次の点滅が始まる前なら1コマだけ遅れて光らせます（点滅の数を音の数と照合できるように）。

### 保存とオフライン

- 状態の保存先：IndexedDB（データベースの名前は `majikaruta-lab`）。配信元のほかのページと容量を分け合う localStorage より大きく、1日分の記録を入れても溢れにくいためです。ブラウザに永続の保存も頼みます。
- 同じ端末の別のタブで実験用のページを開くと、両方のタブに注意を出します（2つのタブが同じ保存先を上書きし合うのを防ぐため）。
- サービスワーカー（`sw.js`）が、ページと部品の写しを端末に残します。一度回線のある場所で開いておけば、回線の無い会場でも再読み込みや開き直しができます。端末が回線につながっているときは、サービスワーカーが常に最新の版を取りに行きます。
- 外部から読み込むものは Google Fonts の書体だけです。読めなくても、端末の書体で崩れずに表示します。

## 音

アプリはすべての音を Web Audio の発振器で作り、「読む」を押した時点で、1回の読みの全部の音を AudioContext の時刻で予約します。setTimeout では鳴らさないので、端末が忙しくても電子音の間隔はずれません。

- 準備音：523 Hz（ド）の三角波を 0.22 秒鳴らし、鐘のように減衰させます。
- 通常の音：880 Hz の正弦波を、t の半分か 0.08 秒の短いほうの長さで鳴らします。
- 最後の音：1760 Hz の正弦波を 0.22 秒鳴らします（赤と黒の黒の札だけ 440 Hz）。
- 準備音の鳴り始めから最初の電子音の鳴り始めまで：公開版は 1.0 秒に固定し、実験用のページでは「設定」で変えられます。

通常の音と最後の音の高さは、同じ案件の収集Bのアプリと同じにしてあります。紙のフリープレイ（収集A）とPCの実験（収集B）で、参加者が聞く音をそろえるためです。

iPhone の Safari では、最初の画面のボタンのタップで AudioContext を起こします。Safari 16.4 以降では `navigator.audioSession.type = "playback"` も設定します。
それでも本体の消音スイッチが入っていると鳴らない場合があるので、最初の画面に注意を出しています。画面が消えないように Wake Lock を使います（使えない端末では何もしません）。

## 配信の仕方

このアプリは GitHub Pages から配信しています。

- 公開版：https://unryu.org/magikaruta-reader/
- 実験用のページ：https://unryu.org/magikaruta-reader/lab.html

ES モジュール（`<script type="module">`）を使うので、`file://` では動きません。手元で動かすときは、このフォルダでローカルのサーバを起こし、http://localhost:8797/ を開きます。

```
python3 -m http.server 8797
```

Wake Lock（画面を消さない機能）とサービスワーカーは HTTPS（または localhost）でしか働かないので、会場の端末では GitHub Pages の URL を使います。

## 検査

純粋な関数を `js/core.js`（2つのページで共有）と `js/lab-core.js`（実験用のページの条件の袋、記録の組み立て、状態の復元、CSV）にまとめ、`test/` で検査します。node 18 以降で動きます。

```
node --test test/*.test.js
```
